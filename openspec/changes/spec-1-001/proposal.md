# Change: spec-1-001

## Summary

Add a Gradio-backed Script Browser & Versioned Prompt Workspace that provides a read-only canonical script store, an editable prompt workspace, and an append-only versioning layer. The UI will be driven by an index.json read model and support live-reload from disk.

## Motivation

Users currently rely on ad-hoc file uploads and flat dropdowns for prompt selection. This change provides a structured, versioned workflow that guarantees immutability of canonical assets, supports safe editing via versioning, and enables fast browsing and live reload.

## Scope

- Create OpenSpec proposal, tasks, and design for the Script Browser & Versioned Prompt Workspace.
- Add a spec delta describing the required runtime behaviours and scenarios.

## Deliverables

- `openspec/changes/spec-1-001/{proposal.md,tasks.md,design.md}`
- `openspec/changes/spec-1-001/specs/spec-1/spec.md`

## Acceptance Criteria

- The proposal and spec validate with `openspec validate spec-1-001 --strict`.
- The spec contains clear scenarios for browsing, preview, copy/append, save-as-new-version, index regeneration, and live reload.

## Why

To provide a reproducible, safe prompt composition workflow and remove accidental mutation of canonical scripts.

## What Changes

- Adds a Gradio UI concept and read-model index for script browsing.
- Introduces a versioned storage layout under `scripts/` with canonical, versions, drafts, and an autogenerated `index.json`.

## Next Steps

1. Implement the UI and storage layer per `tasks.md` after proposal approval.
2. Add tests for index generation and live-reload behavior.
