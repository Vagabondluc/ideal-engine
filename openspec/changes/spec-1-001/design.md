# Design: Script Browser & Versioned Prompt Workspace (Gradio)

## Overview

This design summarizes the storage layout, index format, live-reload mechanism, and high-level Gradio component interactions required by the PRD.

## Storage Layout

Required layout under project root `scripts/`:

```
scripts/
├── canonical/
│   └── <category>/<script>.txt
├── versions/
│   └── <category>/<script>/
│       ├── v1.txt
│       ├── v2.txt
│       └── meta.json
├── drafts/
│   └── session_<uuid>/prompt.txt
└── index.json
```

Rules:
- `canonical/` is read-only at runtime
- `versions/` is append-only
- `drafts/` are session-scoped
- `index.json` is generated by the indexer and is the UI read model

## Index Format (example)

```json
{
  "scripts": [
    {
      "id": "ai_behavior/ed_greenwood",
      "category": "AI_Behavior",
      "canonical_path": "scripts/canonical/AI_Behavior/ed_greenwood.txt",
      "versions": ["v1","v2"],
      "meta": {"author":"curated","notes":""}
    }
  ]
}
```

## Live Reload

- Use `watchdog` to monitor `scripts/canonical/**`, `scripts/versions/**`, and `index.json`.
- On change, rebuild `index.json` and emit a UI reload event in Gradio (client-side refresh of lists).

## Gradio Component Plan

- Category selector (radio or dropdown)
- Search input
- Script list (per-category)
- Read-only preview pane
- Prompt editor (editable textarea)
- Version selector (for chosen script)
- Save-as-New-Version dialog (category, notes)
- Buttons: `Copy → Prompt`, `Append → Prompt`, `Save as New Version`

## Security & Safety

- No writes to `canonical/`.
- Validate any incoming path segments to avoid traversal.
